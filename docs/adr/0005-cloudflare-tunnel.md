# Visitors reach the server through a Cloudflare Tunnel

The spec put nginx behind Cloudflare's proxy with an Origin Certificate, which meant publishing ports 80 and 443 on the server and trusting Cloudflare's published IP ranges. We switched to a Cloudflare Tunnel (2026-10-24): a `cloudflared` container keeps outbound connections to Cloudflare's edge and passes each request to nginx on a private Compose network. The server publishes no port at all, there is no certificate to install, and nobody can reach nginx by going around Cloudflare. nginx still restores the visitor's IP from `CF-Connecting-IP`, but trusts it only from `cloudflared`'s fixed address on that network instead of from Cloudflare's IP ranges, so the IP list no longer needs refreshing. The cost is a tunnel token to keep secret, and a fixed private subnet in `docker-compose.yml` that must not overlap another Docker network on the server.
