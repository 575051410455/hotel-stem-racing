No port is published on the server and there is no certificate to install: TLS ends at Cloudflare's edge, and nobody can reach nginx by going around Cloudflare. Why this setup: docs/adr/0005-cloudflare-tunnel.md.

1. Server

  1. next build runs on the server and can run out of memory on a 1 GB machine. To add 2 GB of swap:

    sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

  2. Follow Docker's Ubuntu guide (the apt repository method). Then let your user run Docker without sudo, log out and back in, and check:

    sudo usermod -aG docker "$USER"
docker compose version

  3. The tunnel needs no inbound port. In the provider's firewall allow inbound 22 only, or with ufw:

    sudo ufw allow OpenSSH
sudo ufw enable

    cloudflared needs to reach Cloudflare on outbound port 7844 (TCP and UDP). Most providers allow all outbound traffic; if yours doesn't, allow that port.

  4. The repository is private. Give the server a read-only deploy key: create it, then add the public key at GitHub → the repository → Settings → Deploy keys → Add deploy key (leave write access off).

    ssh-keygen -t ed25519 -N "" -f ~/.ssh/id_ed25519 -C "stem-racing server"
cat ~/.ssh/id_ed25519.pub

    Then clone:

    sudo mkdir -p {{dir}} && sudo chown "$USER": {{dir}}
git clone {{repo}} {{dir}}
cd {{dir}}

    All later commands run from this folder.

2. Cloudflare Tunnel

The domain must already use Cloudflare's nameservers. Cloudflare's dashboard changes from time to time, so the names below can differ slightly. Cloudflare's own guide has the current steps.

  1. Open Zero Trust → Networks → Tunnels → Create a tunnel. Choose Cloudflared, name it stem-racing and save.

  2. On the "Install and run a connector" step, pick Docker. The command shown ends in --token eyJ…. Copy only that long token, the part after --token. It goes into .env as CLOUDFLARE_TUNNEL_TOKEN in step 4.

    Don't run Cloudflare's docker run command: Compose runs cloudflared for you. Anyone with the token can serve traffic for your hostname, so keep it as secret as a password.

  3. On the next step (Public Hostname, called "published application routes" in newer dashboards) add:

    Subdomain and domain
    Pathleave empty
    Service typeHTTP
    URLnginx:80

    Use nginx:80, not app:3000 and not localhost. cloudflared runs inside Compose, where nginx is called nginx, and it can't reach the app directly.

    Saving adds a proxied DNS record for the hostname: a CNAME to <tunnel id>.cfargotunnel.com. If a record with that name already exists, for example an old A record, saving fails. Delete the old record under DNS → Records, then save again.

3. Cloudflare settings

  1. Go to SSL/TLS → Edge Certificates. Turn on Always Use HTTPS, and set Minimum TLS Version to TLS 1.2. nginx also redirects plain HTTP if this is ever off.

    The SSL/TLS encryption mode doesn't affect tunnel traffic, which is encrypted by the tunnel itself. Leave it as it is.

  2. Under Turnstile, open the registration widget, add as a hostname, and keep the site key and secret key for .env.

4. Fill in .env

  1. cp .env.example .env && chmod 600 .env
sed -i \
  -e "s|^APP_URL=.*|APP_URL=https://{{domain}}|" \
  -e "s|^BETTER_AUTH_URL=.*|BETTER_AUTH_URL=https://{{domain}}|" \
  -e "s|^BETTER_AUTH_SECRET=.*|BETTER_AUTH_SECRET=$(openssl rand -hex 32)|" \
  -e "s|^POSTGRES_PASSWORD=.*|POSTGRES_PASSWORD=$(openssl rand -hex 32)|" \
  .env

    Run this only once, before the first start. The database keeps the password it was created with: running it again would give the app a password the database doesn't know.

  2. VariableValue
    CLOUDFLARE_TUNNEL_TOKENthe token from step 2
    SEED_STAFF_EMAIL: the first Admin Account (step 6). There is no password variable: the command makes one up.
    SEED_STAFF_NAME (defaults to เจ้าหน้าที่)
    NEXT_PUBLIC_TURNSTILE_SITE_KEY, TURNSTILE_SECRET_KEYthe real Turnstile keys. The example values are test keys that let everything through.
    SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS, EMAIL_FROMthe Gmail or Google Workspace account. SMTP_PASS is an app password, written without spaces. EMAIL_FROM must be a verified alias of SMTP_USER. Leave SMTP_USER empty to launch without email.
    NEXT_PUBLIC_CONTACT_LINE, NEXT_PUBLIC_CONTACT_PHONEthe organisers' contact channels. Each is hidden when empty.
    APP_URL, BETTER_AUTH_URL, BETTER_AUTH_SECRET, POSTGRES_PASSWORDalready set by the command above. Check that both URLs read https://, with no trailing slash.
    DATABASE_URL, TEST_DATABASE_ADMIN_URLleave as they are. Compose builds the app's database address from POSTGRES_PASSWORD.
    • NEXT_PUBLIC_* and APP_URL are built into the app. After changing one, rebuild with docker compose up -d --build.
    • Avoid $ in values: Compose reads it as a variable.
    • To change POSTGRES_PASSWORD later, run ALTER USER stem_racing PASSWORD '…' in the database shell (step 9) first, then update .env and run docker compose up -d.

5. Start

  1. docker compose config --quiet && echo "compose OK"
docker compose up -d --build
docker compose ps

    db and app should become healthy, and all four services should be running. The first build takes a few minutes.

  2. docker compose logs app | tail -20
docker compose logs cloudflared | grep -i "registered tunnel connection"
docker compose exec nginx nginx -t
    • app: [migrate] applied N new migration(s), then Ready.
    • cloudflared: up to four lines of Registered tunnel connection. The tunnel then shows as Healthy in Zero Trust → Networks → Tunnels.
    • nginx -t: syntax is ok and test is successful.

  3. The registration page loads. Plain HTTP must redirect to HTTPS:

    curl -sI http://{{domain}} | head -3

    Expect 301 with Location: https://….

  4. Sorting the Registration list by name needs PostgreSQL's ICU collation. This should print 1:

    docker compose exec db psql -U stem_racing stem_racing -Atc "select 1 from pg_collation where collname = 'th-TH-x-icu'"

    If it prints nothing, everything else works, but sorting the list by name fails.

6. Admin Accounts

Operator commands run inside the app container, just like npm run … on a laptop. The container gets its settings from .env through Compose. The line ".env not found. Continuing without it." in their output is harmless.

KindOpensCreated with
Admin Accountthe whole Back Office: Registrations, the overview, CSV export, email and Check-Innpm run seed (the first one), npm run staff -- create-admin
Staff Accountthe check-in desk only (/admin/check-in, with Kiosk mode), for helpers at the entrancenpm run staff -- create
Kiosk Accountthe Kiosk page only (/kiosk), for an unattended iPadnpm run staff -- create-kiosk

  1. It uses SEED_STAFF_EMAIL () and SEED_STAFF_NAME from .env:

    docker compose exec app npm run seed
    • It prints the email and a random password once. Copy the password straight away: it isn't stored anywhere and doesn't appear in docker compose logs.
    • If an Admin Account already exists, it creates nothing and says so, so running it again is safe.
    • If the email already belongs to an Account, it stops and suggests make-admin (below).
    • If it stops because SEED_STAFF_EMAIL is missing or invalid, fix .env, run docker compose up -d so the container picks it up, and run it again.

  2. Sign in at /admin/login with the printed password. Then open the account menu at the foot of the sidebar, choose My Account, and change the password.

  3. Use -it so the command can ask for the password: at least 12 characters, typed twice. Change the email and the name in quotes:

    docker compose exec -it app npm run staff -- create-admin organiser2@example.com "Organiser name"

    Keep at least one Admin at the entrance on Event days: looking an Attendee up by name and re-sending an Event Pass need an Admin Account.

  4. make-admin turns an existing Account into an Admin Account. It needs no password, and it signs that Account out everywhere so it signs in again with the whole Back Office. It is also the way back in if no Admin can sign in:

    docker compose exec app npm run staff -- make-admin {{adminEmail}}

    A lost password: reset-password works for every kind of Account. It asks for the new password and signs that Account out everywhere:

    docker compose exec -it app npm run staff -- reset-password {{adminEmail}}

7. Staff and Kiosk Accounts

  1. docker compose exec -it app npm run staff -- create helper@example.com "Helper name"
  2. docker compose exec -it app npm run staff -- create-kiosk kiosk-1@example.com "Kiosk 1"
docker compose exec -it app npm run staff -- create-kiosk kiosk-2@example.com "Kiosk 2"
    • A Kiosk Account opens only /kiosk and records Check-Ins. Every other page sends it back to the Kiosk, so an Attendee who leaves it reaches no Registration data.
    • One Account per iPad tells the Kiosks apart, and reset-password on a lost iPad's Account signs out that iPad only.
    • The email only identifies the Account; nothing is sent to it.
    • Sessions last 30 days. In Safari, open /admin/login and sign in with the iPad's Kiosk Account. It goes straight to the Kiosk with the front camera; allow the camera.
    • Before the Event a scan shows "วันนี้ไม่ใช่วันจัดงาน / Today isn't an Event Day", which shows that the camera and connection work. To rehearse on a chosen day, use the desk's Kiosk mode (/admin/check-in?kiosk=1) with a Staff Account.
    • Guided Access: Settings → Accessibility → Guided Access, then triple-click the side or top button in Safari. Set Auto-Lock to Never if the Kiosk's Staff panel says it can't keep the screen on.
  4. docker compose exec app npm run email:test -- you@example.com

    Check that it arrives, including in the spam folder.

8. Visitor IP and logs

  1. Visit the site, then:

    docker compose logs --tail 20 nginx

    Each access line starts with <visitor IP> via 10.203.47.2. The visitor IP must be your own public IP: /cdn-cgi/trace shows it as ip=.

    If a line starts with 10.203.47.2 itself, nginx isn't restoring the IP, and every visitor would share one sign-in rate limit. Check that cloudflared's address in docker-compose.yml and set_real_ip_from in deploy/nginx/conf.d/app.conf are the same.

  2. docker compose logs -f app          # app and migrations
docker compose logs --tail 100 nginx
docker compose logs --tail 100 cloudflared
docker compose logs --tail 100 db

    Docker keeps at most 5 × 10 MB of logs per container.

9. Day-to-day

Deploy a new version
cd {{dir}} && git pull && docker compose up -d --build
Migrations run on start. The database volume is untouched.
Restart the app
docker compose restart app
Database shell
docker compose exec db psql -U stem_racing stem_racing
Back up (before the Event and before risky changes)
docker compose exec -T db pg_dump -U stem_racing -Fc stem_racing > stem-racing-$(date +%F-%H%M).dump
Restore (replaces the current data)
docker compose stop app
docker compose exec -T db pg_restore -U stem_racing -d stem_racing --clean --if-exists < file.dump
docker compose start app
Replace the tunnel token
If the token may have leaked, delete the tunnel in Zero Trust and create a new one with the same hostname (step 2), put its token in .env, then run: 
docker compose up -d cloudflared
Update cloudflared
Change the cloudflare/cloudflared tag in docker-compose.yml to a newer release, then docker compose up -d cloudflared. The tunnel reconnects in a few seconds.
Never
run docker compose down -v: -v deletes the database volume and every Registration. Plain docker compose down is safe.

10. Troubleshooting

You seeLikely cause and fix
Cloudflare error 1033cloudflared isn't connected. Check docker compose logs cloudflared: a wrong or missing CLOUDFLARE_TUNNEL_TOKEN, or outbound port 7844 blocked.
502 Bad Gateway from CloudflareThe hostname's service isn't http://nginx:80, or nginx isn't running (docker compose ps).
502 from nginxThe app isn't ready or crashed. Check docker compose logs app.
Pool overlaps with other one on this address spaceAnother Docker network on the server already uses 10.203.47.0/28. Pick another private /28 in docker-compose.yml (the subnet, ip_range and cloudflared's address) and change set_real_ip_from in app.conf to match.
required variable CLOUDFLARE_TUNNEL_TOKEN is missingEvery docker compose command needs it. Fill it in .env.
Sign-in fails with 403BETTER_AUTH_URL isn't exactly https://. Fix .env, then docker compose up -d.
The registration form's bot check failsThe Turnstile keys are wrong, or the hostname isn't on the widget (step 3). After changing the site key, rebuild with docker compose up -d --build.
Error 524A request took longer than Cloudflare's 100 s limit. Bulk email works in batches that each finish well within it.

Notes

  • Timeouts: nginx allows requests of up to 300 s, but Cloudflare ends any request after 100 s with error 524 on non-Enterprise plans.
  • Client IP for the app: nginx sends the restored visitor IP as X-Real-IP and sets X-Forwarded-For to that same single address. It removes CF-Connecting-IP and True-Client-IP before proxying.
  • Streaming: nginx doesn't buffer the app's responses (proxy_buffering off), so pages stream through.
  • Files: docker-compose.yml, deploy/nginx/conf.d/app.conf, .env.example and Dockerfile in the repository.
